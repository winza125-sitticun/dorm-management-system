## Control Plane D1 schema

### `licenses`

Required fields:

- `id TEXT PRIMARY KEY`
- `key_hash TEXT NOT NULL UNIQUE`
- `customer_label TEXT`
- `plan TEXT NOT NULL`
- `status TEXT NOT NULL`
- `max_activations INTEGER NOT NULL DEFAULT 1`
- `expires_at INTEGER`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

Required checks:

- `plan IN ('basic','standard','pro')`
- `status IN ('active','suspended','revoked','expired')`
- `max_activations >= 1`

### `activations`

Required fields:

- `id TEXT PRIMARY KEY`
- `license_id TEXT NOT NULL`
- `installation_id TEXT NOT NULL`
- `project_name TEXT`
- `primary_hostname TEXT`
- `activated_at TEXT NOT NULL`
- `last_seen_at TEXT NOT NULL`
- `revoked_at TEXT`

Required constraints:

- foreign key `license_id -> licenses(id)`
- `UNIQUE(license_id, installation_id)`

`installation_id` is supplied by the customer installation and is never generated by the Control Plane.

### `license_events`

Required fields:

- `id TEXT PRIMARY KEY`
- `license_id TEXT`
- `installation_id TEXT`
- `kind TEXT NOT NULL`
- `ip_hash TEXT`
- `user_agent_hash TEXT`
- `created_at TEXT NOT NULL`

The schema must not contain raw license-key, raw IP, raw User-Agent, customer business-data, or customer credential columns.

## License-key hash contract

Task 4 stores no plaintext license key.

Normalization is exactly:

1. accept a string
2. trim leading/trailing whitespace
3. reject empty result
4. do not change letter case or internal characters
5. UTF-8 encode
6. SHA-256 hash
7. encode digest as lowercase hexadecimal

Required interface:

```ts
export async function hashLicenseKey(rawLicenseKey: string): Promise<string>;
```

The returned lowercase hex string is the only value persisted as `licenses.key_hash`.

Errors and logs must never include the raw license key.

## Task 3 token compatibility

Task 4 signer output must be accepted by the exact Task 3 verifier contract:

```text
dormlic1.<payload-base64url>.<signature-base64url>
```

Canonical V1 payload key order remains exactly:

```text
v
licenseId
installationId
plan
status
issuedAt
expiresAt
refreshAfter
```

Signature input is the UTF-8 bytes of the canonical JSON payload, not the envelope or base64url text.

Task 4 may implement a vendor-side canonicalizer, but tests must prove byte-for-byte compatibility against the Task 3 canonical contract. Task 4 must not change the customer verifier or wire format.

## Private signing key contract

The Control Plane private key is supplied only through the Worker secret:

```text
LICENSE_SIGNING_PRIVATE_KEY
```

Text representation is:

```text
PKCS#8 DER bytes -> unpadded base64url
```

Required interface:

```ts
export async function importLicenseSigningPrivateKey(
  pkcs8Base64Url: string,
): Promise<CryptoKey>;
```

Import uses Web Crypto Ed25519 and returns a non-extractable signing key where runtime support permits.

The private key value must never appear in git, `wrangler.template.jsonc`, environment examples, customer Master/PREVIEW ZIPs, logs, test snapshots, or CI artifacts. Tests generate ephemeral Ed25519 keypairs at runtime only.

## Signing interface

Required payload type:

```ts
export interface SignLicensePayloadInput {
  licenseId: string;
  installationId: string;
  plan: 'basic' | 'standard' | 'pro';
  status: 'active' | 'suspended' | 'revoked' | 'expired';
  issuedAt: number;
  expiresAt: number;
  refreshAfter: number;
}
```

Required signer:

```ts
export async function signLicenseToken(
  payload: SignLicensePayloadInput,
  privateKey: CryptoKey,
): Promise<string>;
```

The signer must construct V1 with `v: 1`, reject empty IDs and unsupported plan/status, require finite integer epoch-second timestamps and `issuedAt <= refreshAfter <= expiresAt`, canonicalize exactly as Task 3, Ed25519-sign canonical UTF-8 bytes, return the exact `dormlic1` envelope, and never log token/private-key bytes.

Task 4 does not enforce activation seat counts in the signer.

## Repository boundary

`licenseRepository.ts` is limited to database primitives needed for later APIs and Task 4 schema verification. It may expose functions to read a license by ID/hash and list/count activations, but Task 4 must not implement API-level activation mutation flows or seat-allocation transactions.
