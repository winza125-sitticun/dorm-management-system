# V15 Task 1 White-label Schema + Plan Entitlements + Settings Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the V15 Task 1 white-label foundation to the immutable V14 CUSTOMER-READY codebase: schema v7, `whiteLabel` entitlement, owner-scoped settings contract, strict validation, backward-compatible backup/restore, and package parity.

**Architecture:** Start from the exact V14 R3-CI candidate proven by source/release run `31980850645` and real D1 smoke run `31990279000` attempt 2. Keep white-label as a single plan feature, store additive nullable columns on `settings`, derive `whiteLabelEnabled` from the subscription plan, gate only actual post-normalization white-label changes, preserve Demo first-setup naming, and evolve `.dormbackup` from schemaVersion 6 to 7 without changing formatVersion 1.

**Tech Stack:** TypeScript, React/Vite, Cloudflare Pages Functions, Cloudflare D1, Zod, Node.js `node:test`, package builder scripts, GitHub Actions.

## Global Constraints

- Base source is the exact V14 R3-CI candidate generated by source/release run `31980850645`; do not independently patch Demo/Basic/Standard/Pro ZIPs.
- V14 real D1 smoke run `31990279000`, attempt 2, is the behavioral baseline and must remain green after Task 1.
- White-label entitlement matrix is fixed: Demo=`false`, Basic=`true`, Standard=`true`, Pro=`true`.
- PromptPay entitlement semantics remain unchanged: Demo=`true`, Basic=`false`, Standard=`true`, Pro=`true`.
- Demo may set `dormName` during `POST /api/setup/init`; only post-setup white-label mutations are gated.
- White-label writable settings in Task 1 are `dormName`, `brandColor`, `contactPhone`, and `billFooter`.
- `brandLogoKey` is server-managed and non-portable; `brandLogoUrl` is read-only and may remain `null` in Task 1.
- New D1 columns are additive and nullable; do not rename or drop V14 fields.
- `.dormbackup` remains `formatVersion=1`; new V15 exports use `schemaVersion=7`.
- V15 must still validate and restore V14 `schemaVersion=6` backups.
- V14 backup exclusions, owner scoping, restore token binding, `RESTORE` confirmation, `Cache-Control: no-store`, LINE/Google/subscription preservation, and D1-only restore behavior remain unchanged.
- Unknown or read-only white-label fields must be rejected, not silently saved.
- No UI theme rendering, logo upload, bill rendering changes, PWA icon work, or unrelated Settings refactor in Task 1.

const COLOR_RE = /^#[0-9A-Fa-f]{6}$/;

Normalization rules:

Implement diffing against normalized/current values:

```ts
export function changedWhiteLabelFields(current: Record<string, unknown>, patch: NormalizedWhiteLabelSettings): string[] {
  return (Object.keys(patch) as Array<keyof NormalizedWhiteLabelSettings>)
    .filter((key) => patch[key] !== normalizeCurrentValue(key, current[key]))
    .map(String);
}
```

The helper must return `[]` when Demo submits a full form containing the unchanged `dormName`.
